# dynamic_graph

Алгоритм реализует операцию изменения веса ребра и пересчет кратчайших расстояний только в затронутой части графа.
Для использования нужен только файл dynamic_graph.py
## Вход

Граф задается списком ребер и списком смежности

Вершины нумеруются `1 .. N`. Индекс `0` в массивах не используется.

- Число вершин в графе
- `graph[v]` — список соседей `v`. Ребро записывается в обе стороны.
- `W[(u, v)]` и `W[(v, u)]` — один и тот же вес, число `> 0`
- Номер стартовой вершины
## Пример

Источник — вершина `1`. Один и тот же граф задан списком рёбер и списком смежности.


Предполагается что задается неориентированный граф

```python
from collections import defaultdict
from math import inf
from dynamic_graph import DynamicGraph, full_dijkstra

# список рёбер: (начало, конец, вес)
edges = [
    (1, 2, 1),
    (2, 3, 1),
    (3, 4, 1),
    (1, 3, 4),
    (2, 4, 8),
]

# список смежности: вершина -> соседи
graph = defaultdict(list)
graph[1] = [2, 3]
graph[2] = [1, 3, 4]
graph[3] = [2, 1, 4]
graph[4] = [3, 2]

W = defaultdict(lambda: inf)
for a, b, w in edges:
    W[(a, b)] = W[(b, a)] = w

g = DynamicGraph()
g.init(4, graph, W, 1) # 4 - число вершин, 1 - стартовая вершина

g.changeEdgeWeight(2, 3, 10)  # поменять вес у ребра 2-3 на 10 и пересчитать расстояния
g.changeEdgeWeight(1, 3, 2)

# g.d[1:] == [0, 1, 2, 3]
print(g.d) # вывести обновленные кратчайшия расстояние от 1 до всех вершин
```


## Поля DynamicGraph

| Поле | Смысл                                                                                                                                   |
|---|-----------------------------------------------------------------------------------------------------------------------------------------|
| `g.d[v]` | Расстояние от источника.                                                                                                                |
| `g.P[v]` | Родитель в дереве.                                                                                                                      |
| `g.childrens[v]` | Список детей вершины v                                                                                                                  |
| `g.W` | Текущие веса в графе                                                                                                                    |
| `g.fallback` | Доля вершин: если затронутых вершин больше `fallback * N`, увеличение веса считается заново Дейкстрой. По умолчанию `1` (не вызывается) |


## Операции

```python
g.changeEdgeWeight(a, b, new_w)  # уменьшение или увеличение веса
g.changeStart(4)                 # Изменить стартовую вершину. Приведёт к recompute()
g.recompute()                    # Запуск дейкстры и пересчет полей
```

После вызова этих функций обновляются поля у объекта DynamicGraph

## Описание работы методов

### `init`

Конструктор создаёт объект с незаполненными полями и значением `fallback`, равным `1`. Метод `init(N, graph, W, start)` сохраняет число вершин, список смежности, веса и источник, строит внутренний список рёбер с весами и вычисляет кратчайшие пути алгоритмом Дейкстры. По полученным родителям восстанавливается дерево: `P[v]` задаёт родителя вершины, `g.childrens[v]` — список её детей. Источник получает расстояние `0` и родителя `-1`. Недостижимая вершина сохраняет расстояние `math.inf` и родителя `-1`.

Повторный вызов `init` заново строит расстояния и дерево по переданным данным. Значение `fallback`, заданное у объекта, при этом сохраняется. Методы `changeEdgeWeight` и `changeStart` до первого вызова `init` завершаются с ошибкой `RuntimeError`.

### `changeEdgeWeight`

Метод `changeEdgeWeight(x, y, new_w)` записывает новый вес ребра в обоих направлениях и пересчитывает кратчайшие расстояния и дерево. Порядок концов ребра произволен. Текущий вес читается из `W`; отсутствующая пара вершин рассматривается как ребро веса `math.inf`. При равенстве нового и текущего веса поля не изменяются.



Поле `g.fallback`  умолчанию равно `1`.

```python
g.fallback = 0.3
```

При значении `1` порог равен `N`. В поддереве не больше `N` вершин, поэтому увеличение веса завершается локальным разбором. Такой разбор быстрее полной Дейкстры, пока поддерево небольшое. При большом поддереве его трудоёмкость сопоставима с одним полным пересчётом. Значение `0.3` сохраняет локальный разбор для поддерева в пределах 30% вершин и переводит более крупные увеличения на `recompute`. Вызовы `changeStart` и `recompute` выполняют Дейкстру по всему графу при любом значении `fallback`.

### `changeStart`

Метод `changeStart(start)` заменяет источник и вызывает `init` с текущими числом вершин, списком смежности и весами. Расстояния и дерево строятся заново от новой стартовой вершины. Значение `fallback` сохраняется.

### `recompute`

Метод `recompute` повторно вызывает `init` с текущими числом вершин, списком смежности, весами и источником. Расстояния и дерево вычисляются Дейкстрой по всему графу. Значение `fallback` сохраняется. Внутренний список рёбер при этом строится заново из списка смежности и `W`, поэтому в списке смежности должны присутствовать все рёбра, которые требуется учесть.

### Ограничения

Алгоритм применяется к неориентированному графу с одним источником и положительными весами. При нулевом весе порядок обхода поддерева по прежнему расстоянию перестаёт соответствовать зависимостям путей. Объект не рассчитан на одновременные вызовы из нескольких потоков.

## Описание алгоритма


Алгоритм поддерживает T - дерево кратчайших путей от старта до всех вершин.
В коде оно реализовано с помощью хранения для каждой вершины списка потомков childrens и предков P. 
Алгоритм отдельно обрабатывает увеличение и уменьшение ребра.

**Опр**. `Затронутая вершина` - вершина для которой изменение какого то ребра могло повлечь изменение кратчайшего расстояния до этой вершины

Далее всегда будем считать, что x это предок y


### Уменьшение ребра (incremental dijkstra)
incremental взят отсюда
https://www.tandfonline.com/doi/epdf/10.1016/j.akcej.2020.01.002?needAccess=true

***Утверждение 1***:
Любая затронутая вершина будет таковой из-за уменьшения какого-то ребра (x, y). Все затронутые вершины будут находиться в поддереве кратчайших путей T(y). Утв. 4 из статьи

107 строка: изменяется вес у ребра (x, y)

108-111: поля объекта записываются в локальные переменные для оптимизации

112-113: Не умаляя общности будем считать, что `x` встречается раньше чем `y` в T 

114-115: Если мы уменьшили ребро (x, y), но кратчайшее расстояние `d[y]` все равно меньше чем `d[x] + newW`, значит существует более хороший путь. Алгоритм завершается

116: Изменяем дерево кратчайших путей T, теперь в y попадаем через x.

120-131: Проталкиваем изменение из вершины y дейкстрой и поддерживаем T.

В статье корректность доказывается формально через мат индукцию и разбор случаев
Но из утв. 1 понятно что достаточно пропушить изменения из измененной вершины по поддереву

### Увеличение ребра (decremental dijkstra)

decremental — это Algorithm 2 из той же статьи:
https://www.tandfonline.com/doi/epdf/10.1016/j.akcej.2020.01.002?needAccess=true

***Утв. 1*** d`[x] >= d[x] - новые расстояние могут стать только больше после увеличения ребра

Алгоритм красит все затронутые вершины в 2 цвета. В красный - необработанные и в белый - обработанные.
На каждом шаге из кучи извлекается вершина `v`, для нее ищется предок через который можно для `v` получить минимальное кратчайшее расстояние.
Если предок с минимальным расстоянием красный, то для текущей вершины нельзя точно знать ответ, `v` будет добавлена в кучу снова одним из предков, когда он станет белым. Если белый - то по утверждению 1 (белые предки хуже, красные лучше не станут) для `v` теперь известно через него корректное расстояние.
Далее добавятся в очередь для рассмотрения потомки и соседи `v`. 

135: алгоритм меняет вес ребра

142-146: если ребро не входит в `T`, затронутых вершин не будет и алгоритм завершается. Иначе нижний конец ребра — `y`, верхний — `x`

148-157: все вершины поддерева `T(y)`, включая `y`, красятся в красный

158-160: если таких вершин больше `fallback * N`, вызывается `recompute` и локальный разбор не идёт

195: Куча инициализируется концом измененного ребра - `y`

207-209: у извлечённой вершины запоминается старое расстояние, новое временно становится `inf`, родитель снимается

214-223: `pred_min` выбирает соседа с наименьшей суммой `d[p] + w`. При равенстве сумм предпочтение у белой вершины. Сосед с расстоянием `inf` или ребром веса `inf` не рассматривается

226-228: если лучший сосед красный, вершина ещё не зафиксирована. Она снова кладётся в кучу с ключом `inf` и будет извлечена после этого соседа

230-232: если лучший сосед белый, вершина получает его расстояние и родителя и сама красится в белый

234-240: если расстояние изменилось, дети в дереве кладутся в кучу со своим текущим расстоянием. Остальные соседи кладутся в кучу, когда путь через эту вершину строго короче их текущего расстояния

241-242: если расстояние не изменилось (существует другой путь с таким же расстоянием), поддерево красится в белый. Увеличение ребра ни на что ни повлияет
